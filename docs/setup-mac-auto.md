# Mac 完全自動化のセットアップ（書き出しから push まで無人）

毎朝、Mac が自分で LINE を開いてトークを txt に書き出し、このリポジトリに
push するようにする。**設定後はこちらの操作はゼロ**。

```
毎日 07:00 以降の離席中  Hammerspoon（mac/line_export.lua v4.1）
  → LINE を開く → 一覧に見えているトークはそのまま、見えなければ検索して開く
  → ⋮ → トークを保存
  → Linetxt フォルダに [LINE]<トーク名>_YYYYMMDD.txt（日ごとのスナップショット）
  → mac/sync.sh: ingest.py で chats/ に取り込み → commit → push
  → GitHub の line-dump が最新に（Cowork / Claude からいつでも読める）
失敗したら → 撮影画像と診断（伏せ字）を Dropbox の Backups/line-dump-debug に置く
```

## 困ったら、まずこれ

Hammerspoon のコンソール（メニューバーの金槌 → Console）に打つ。結果も
コンソールに出る（コンソールが LINE の後ろに隠れないよう、前に出してから書く）。

| 打つもの | 何が分かるか |
|---|---|
| `__LINE_EXPORT.status()` | 今の状態。**自動実行が走らない理由**（画面ロック・使用中・画面がすぐ消える設定・main 以外のブランチ など）と、最後の確認でなぜ見送ったか |
| `__LINE_EXPORT.check("Berry")` | 1件を、保存ダイアログで保存名を確かめるところまで試す（確かめたらキャンセルする。**保存はしない**）。段ごとに ✓ / ✗ が出て、✗ なら詳しく・画像・次にすることが出る |
| `__LINE_EXPORT.one("Berry")` | 1件だけ本当に書き出して push |
| `__LINE_EXPORT.diag()`（`⌘⌥⌃K`） | 画面の読み取り診断。**何も押さない**（最小化された LINE も戻さない）。検索欄・一覧の境目・ヘッダ・⋮ の位置と、TARGETS が一覧に見えるか |
| `__LINE_EXPORT.names()`（`⌘⌥⌃J`） | 一覧に見えているトーク名を、`TARGETS` に貼れる形で出す（一覧の列だけを読む。会話の中身は出ない） |
| `__LINE_EXPORT.update()` | 今すぐ最新の版にする（`git pull` して、うまくいった時だけ読み込み直す。失敗したら理由を出す）。ふだんは自動更新に任せてよい |
| `__LINE_EXPORT.help()` | この一覧 |

**`status`・`check`・`one`・`diag` と書き出しのログに出る画面の文字は伏せ字。**
`TARGETS` の名前と LINE の決まった表示（「トークを保存」などのメニュー項目）以外は
`■12字` のように字数だけになる（時刻などの数字は `［数字］`）。そのまま貼って
共有しても、会話の中身や他のトーク名は出ない。`names()`（`⌘⌥⌃J`）だけは
`TARGETS` に貼るためのトーク名の一覧を出す（会話の中身は出さない）。
`sync.sh` の出力（取り込んだファイル名が入る）はコンソールに出さず、
`mac/sync.log` にだけ書く。

`check` と `diag` の結果、自動実行の結果は、Dropbox の
`Backups/line-dump-debug/latest.txt`（伏せ字）にも書く。失敗した時の撮影画像も
同じ所に置く（こちらは LINE の窓そのまま。非公開の Dropbox だけに置き、公開の
リポジトリには入れない。他のアプリが前にある時は撮らない。7日で消える）。
新しい版を初めて読み込んだ時は、何も押さない診断を1回だけ自動で撮っておく
（画面ロック中・カメラ使用中などは撮らない）。

## 画面を読んでから押す

v3 までは「⋮」「トークを保存」を窓の右上からの**固定座標**で押していた。
窓サイズ・ステージマネージャ・メニューの型（1:1/グループと公式で項目数が違う）・
LINE の更新のどれかが変わるとズレ、2026-10-14〜18 は 13 件全滅した。
このメニューは AX にもキーボードにも乗らない独自ウィジェットなので、
測り直しでは弱さが消えない。

v4 からは**画面を撮って OCR で文字を読み、見つけた所を押す**。OCR は macOS 標準の
Vision を `mac/ocr.applescript` から呼ぶ（追加インストール不要）。
1トークごとに、各段で画面を読み直して確かめてから次へ進む。

| 段 | やること | 確かめ方 |
|---|---|---|
| 0. 今の名前 | 1日1回、書き出しの前に検索欄を空にしてトークの一覧を上から下までスクロールしながら読み、今のトーク名を集めて Dropbox の `Backups/line-dump-debug/names.txt`（非公開）に書く。`TARGETS` ごとに近い名前の候補も書く | 各行の時刻と同じ高さの文字だけを名前とみなす（その下の最後のメッセージは読まない）。候補は書き出しには使わない（下の「保存名は完全一致」） |
| 1. 窓 | LINE のメイン窓を前面・キー窓にし、画面いっぱいにする | 検索欄のある窓があり、LINE が前面か。無ければ `open -b`（Dock クリック相当）で開き直す |
| 2. トーク | 今の一覧に名前がそのまま見えていればその行を押す。見えなければ検索欄に名前を貼り付けて、出てきた行を押す | ヘッダ（検索欄と同じ高さ）を OCR して、開いたトークの名前が押した行と同じ強さで合うか。表示が遅れても4秒までは読み直す。LINE が教える検索欄の位置は、フルスクリーンか窓かで画面とずれる（実機でフルスクリーンの時 30pt）ので、毎回検索欄の文字を OCR してずれを測ってから使う |
| 3. メニュー | ⋮（窓右端−24pt・ヘッダのトーク名と同じ高さ）を押す | OCR で「トークを保存」を探し、見つかった所だけ押す |
| 4. 保存 | 保存シートで →キー＋`_YYYYMMDD` → 保存 →（同名なら）置き換え | トークの保存ダイアログか（`[LINE]` で始まる名前・保存とキャンセル）、既定名がトーク名と合っているか |
| 5. 確認 | 保存先から Linetxt へ移す | Linetxt に今日付きのファイルがあれば OK |

- **型指定（1:1/公式）と較正は不要。** メニューの何番目かではなく
  「トークを保存」という文字を探すため
- **一覧とトーク欄の境目は、一覧の AX のセルの右端から割り出す。** 実機では
  検索欄の AX の枠が一覧の幅より狭く、検索欄の右端を境目にすると一覧の文字を
  ヘッダと取り違えた（2026-10-22 の「トーク確認」の失敗）。セルが読めない時は
  仕切り（AXSplitter）、それも無ければ検索欄の右端で代える
- ヘッダのメンバー数の後ろにアイコンを字として読むことがある（「（5）→ ビ」）。
  メンバー数の後ろの3字までは名前の照合から外す
- 一覧の行で別のトークが開いたら、検索して開き直す。一覧から選ぶのは検索欄が空の
  時だけ（前の件の検索結果の「メッセージ」の行などからは開かない）。窓の下に
  はみ出した行は見えていないとみなす
- **Escape は使わない。** LINE は Escape で窓やトークを閉じる（10/14 の連鎖失敗の元凶）。
  メニューを閉じたいときはヘッダのトーク名を押す
- ⋮ を押してもメニューが出なければ、押す前の画面でヘッダの右端に読めた ⋮ を**1回だけ**押し直す（隣のボタンに当たらないよう、1回目より 8pt を超えて左の物は押さない。読めなければ押し直さない）
- ⋮ を押す前から画面にあった文字（本文中の「トークを保存」など）は押さない
- 一覧とヘッダは LINE の窓だけを撮る（通知バナーを読まない）。メニューだけは
  別窓として出る場合に備えて画面を撮り、⋮ の左下の範囲だけを見る
- クリック・キー入力の前に、LINE が前面にあり、押す所に通知など別の物が
  重なっていないことを確かめる（他のアプリを操作しない）。前面が一瞬外れて
  いたら1回だけ LINE を前に出し直し、それでも違えば押さない（その時の前面の
  アプリ名をログに残す）
- 検索欄にフォーカスが入ったと確かめてから打つ（前のトークの入力欄に貼らない）
- 名前は**貼り付けで入れる**（キー入力だと日本語入力が ON のとき崩れるため）。
  入ったのを確かめてからクリップボードを元に戻す。一時的な中身には
  クリップボード履歴アプリに残らない印を付ける
- 保存先はダイアログの既定のまま（⌘⇧G でのパス直打ちはしない）。保存後に
  ダウンロード等から Linetxt に移す
- 実行中は画面を消さない（途中で消えてロックされると、残りが全部失敗する）。
  終わったら元に戻す

**失敗したとき**は、その時点の画面を Dropbox の `Backups/line-dump-debug/` に
保存し、`mac/heartbeat.txt` に「どの段で、なぜ失敗したか＋画像の名前」を書いて push する。

```
failures:
  - Berry: [トーク確認] 開いたトークが違う（またはヘッダの名前が読めない）（画像: Dropbox の Backups/line-dump-debug/20261023-070312_Berry_トーク確認.jpg）
debug: Dropbox の Backups/line-dump-debug（撮影画像と診断。非公開）
```

- heartbeat は GitHub に push するので、決まった文言と画像の名前だけを書く
  （このリポジトリは private にしておく。README の「プライバシー」）。
  ヘッダに見えた名前・保存名などは伏せ字にして、コンソールと
  `latest.txt`（Dropbox）にだけ出す
- 画像はリポジトリには入れない（トーク画面が写るため）。`sync.sh` も、
  画像ファイルが commit に入りそうになったら push せずに止まる

**人が戻ってきたら止まる。** 実行中にマウスを動かすかキーを押すと、その場で
全体を止める（以降は LINE を前に出さない）。heartbeat に `note: 中断: …` と書く。
止めた時は、その時の無操作時間などの数字をコンソールに残す（触っていないのに
止まる時の手がかり）。1回の実行が20分を超えた時も止める（LINE が固まった時。
`status()` には「最後: 時間切れ（20分）」と出る）。自動実行で中断した日は、
また離席したら続きからやり直す（その日に書き出せたトークは飛ばす。1日3回まで）。始める時は、手が離れて静かに
なるまで最大10秒待つ（ホットキーや「許可」を押した直後の手の動きで止まらない
ように。静かにならなければ始めない）。

**画面を見ている人がいそうな時は始めない。** 07:00 以降で3分触っていなくても、
カメラを使用中・画面スリープを止めているアプリがある（ビデオ会議・画面共有・
動画）時は見送る。トークを次々に開く様子が共有画面などに映らないように。
Amphetamine・Caffeine などの「起こしておくだけ」の道具は数えない。

**昼になっても走れていない日は**、heartbeat に `note: 見送り中: <理由>` と書いて
push する（画面がロック中・使用中・カメラ使用中 など。1日1回。読み込み直しても増えない）。
07:00 の間 Mac が眠っていた日は、昼を待たずに起きた後の確認で
`note: 見送り中: <理由>（07:00 は Mac が眠っていた: 00:41〜09:52）` と書く。

**Mac が眠った・起きた・ロックした時刻を記録する**（`mac/.power_log`。この Mac だけの
記録で push しない）。診断ファイルの「最近の眠り・ロック」「Mac が眠るまで」「電源」の行で、
07:00 に走らなかったのが眠っていたからか・ロックされていたからかが分かる。
眠っている間は何も動けないので、その日は起きている間に3分触らなければ始まる。

**始められない時は**（画面収録の許可が無い・保存先のフォルダが無い・OCR スクリプトが
無い）、heartbeat に理由を1日1回書き、その日は済みにしない。直れば次の確認で自動で
始める（`status()` に「始められない（理由）」と出る）。

**自動更新**（2026-10-23 に了承を得て入れた）: 30分ごとと自動実行の後に、GitHub の
main から `git pull --ff-only` し、`line_export.lua` が変わっていれば読み込み直す。
直した版が、この Mac で手を動かさずに使われる。
- 書き出しの実行中・main 以外のブランチでは何もしない
- 新しい版に文法の誤りがあれば読み込まない。読み込みに失敗したら元の版に戻す
  （同じ中身では2度試さない。次の版を待つ）
- 手元で `line_export.lua` を書き換えたままだと `git pull` が失敗し、今の版のまま動く
  （`status()` に「自動更新: … git pull に失敗」と出る）
- 止めたい時は `line_export.lua` の `AUTO_UPDATE` を `false` にする

**新しい版を読み込んだ日は**、その日に失敗していたトークだけを、離席した時に
もう一度試す（版ごとに1回。書き出せたトークは飛ばす）。

**LINE が起動していなければ**、起動だけして次の確認（1分後）で実行する
（起動直後の LINE は同じ処理の中からは見えないため）。その日の回数は使わない。

条件の確認は1分ごと。3分触らずにいると始まるので、画面が3分以内に消えて
ロックされる設定だと、自動実行が始まらない（`status()` に ✗ で出る）。
その場合は システム設定 → ロック画面 で「ディスプレイがオフになるまで」を
5分以上にする。

実行中は AX の応答待ちを2秒にし、終わったら macOS の既定に戻す。`init.lua` で
`hs.window.timeout(…)` を設定しているなら、`line_export.lua` の
`AX_TIMEOUT_AFTER` を同じ値にする。

**ファイル名に書き出し日を付ける理由**: LINE の既定名は毎回同じなので、
そのままだと前回分を上書きしてしまう。書き出しは「画面に読み込まれている
範囲」しか取れず、後から少ないファイルができることがあるため、上書きは
履歴を失う事故につながる。日付を付けて日ごとに残し、取り込み側
（`ingest.py`）が重なりを見て1つの正本にまとめる。

## 前提

- Mac 版 LINE がログイン済み
- 07:00 以降に、Mac が起動・ログインしていて、**画面がロックされておらず**、
  3分以上触っていない時間がある（スリープ中・ロック中は動かない）
- [Hammerspoon](https://www.hammerspoon.org/) 導入済み（`brew install --cask hammerspoon`）
- Hammerspoon に **アクセシビリティ** と **画面収録** の許可（下の手順 3）

## 手順

### 1. リポジトリを Mac に clone

```bash
git clone https://github.com/denkingon/line-dump.git ~/Document/line-dump
```

### 2. 書き出すトークを確認（設定済み）

`~/Document/line-dump/mac/line_export.lua` の `TARGETS` に対象が入っている。
**名前だけ**でよい（型指定は不要）。増やしたいときは同じ形式で足す。

名前の照合は**絵文字・空白・グループのメンバー数「（82）」を無視**する。

- 一覧で行を探す時は部分一致も使う（「…」で切れた名前や OCR の読み違いに
  耐えるため）。完全に一致する行があればそれを開く（「かにっこにー」は
  「かにっこにー3」ではなく「かにっこにー」を開く）。完全一致が無ければ、
  名前より余分な字が少ない行から3つまで順に開き、下の保存名の確かめで
  別のトークと分かれば保存せずに次を開く（名前に絵文字が付いたトーク
  「パプリカ🌶️」を、OCR が絵文字を別の字に読んでも開けるように）
- **今のトーク名は names.txt に集める。** `TARGETS` の名前は、LINE でトーク名を
  変えると古くなる。1日1回、書き出しの前に一覧を上から下まで読んで今の名前を集め、
  Dropbox の `Backups/line-dump-debug/names.txt` に書く。`TARGETS` ごとに近い名前を
  近さ付きで3つまで書くが、**書き出しには使わない**。「Berry」と「Berry2」、
  「村田研」と「村田研OB会」のように、名前を変えたのか別のトークなのかは名前だけでは
  見分けられないため（似た名前に結び付けて別のトークを書き出し、公開リポジトリに
  載せてしまわないように）。名前が変わっていたら names.txt を見て `TARGETS` を直す
- **保存名は完全一致を求める。** 保存ダイアログの既定名（`[LINE]<トーク名>.txt`）は
  LINE が付ける正確な名前なので、ここで `TARGETS` の名前と比べ（絵文字・空白は除く）、
  違えば保存せずに止める。目的のトークが一覧から消えていて、名前を含む別の
  トーク（「村田研」に対する「村田研OB会」）だけが見つかった時も、ここで止まる
- だから `TARGETS` は LINE の表示名そのまま（絵文字・空白は省略してよい）にする。
  `names.txt` の名前を貼るのが確実

**トーク名を一括で取りたいとき**は、Hammerspoon 読み込み後に `⌘⌥⌃J`
（`__LINE_EXPORT.names()` と同じ）。表示中のトーク名が `TARGETS` の形式で
コンソールに出力されるので、そのまま貼れる（トークリストの行は AX で読めるため。
⋮ と違ってツリーに乗っている）。表示中の行しか取れないので、全部欲しければ
リストをスクロールしてからもう一度。一覧の列だけを読むので、トーク欄の
メッセージは出ない（TARGETS に貼るための一覧なので、トーク名は伏せ字にしない）。

保存先（`OUT_DIR`）は既定で既存の Dropbox アーカイブ
`~/Library/CloudStorage/Dropbox-SFC-CNS/Ryo Murata/Backups/Linetxt` を指している。
過去の書き出しもそこに溜まっているので、変えない方が履歴が分断されない。
撮影画像と診断はその隣の `Backups/line-dump-debug` に置く。

### 3. Hammerspoon に権限を与える（1回だけ）

システム設定 → プライバシーとセキュリティ で、Hammerspoon を ON にする。

- **アクセシビリティ**（クリック・キー入力・AX。v3 から許可済み）
- **画面とシステムオーディオ録音**（v4 で必要。画面を撮って OCR するため）
- **ファイルとフォルダ** → ダウンロード・書類・デスクトップ（v4 で必要になりうる）。
  保存ダイアログの既定の保存先がこれらのどこかだと、保存後に Linetxt へ移すときに
  アクセスする。手動実行（`⌘⌥⌃L`・`check`・`one`）の始めにこの3つに
  一度触るので、手順 5 で確認ダイアログが出たら「許可」を押しておく
  （無人の 07:00 に初めて出ると、誰も押さずに止まってしまう）

許可したら Hammerspoon を再起動する（権限は再起動後に効く）。
画面収録が未許可のまま実行すると、何も押さずに止まり、heartbeat に
「画面収録が許可されていない」と書く。

### 4. Hammerspoon に読み込ませる

Hammerspoon コンソールで1行実行（`~/.hammerspoon/` はこちらから書けないため）:

```lua
local f = io.open(os.getenv("HOME").."/.hammerspoon/init.lua","a"); f:write('\ndofile(os.getenv("HOME").."/Document/line-dump/mac/line_export.lua")\n'); f:close()
```

続けてメニューバーの金槌アイコン → **Reload Config**。
コンソールに `[line-dump] 読込完了 v4.1-xxxxxxxx` が出れば稼働（`xxxxxxxx` は
中身から作る印で、版が変わると変わる。heartbeat の `version:` と同じ）。

v3 から使っている場合は、`init.lua` にこの行がもう入っているので不要。

**新しい版が main に入ったら**、自動更新が30分以内に取り込む。すぐ使いたい時は
コンソールで `__LINE_EXPORT.update()`（`git pull` して、うまくいった時だけ読み込み直す）。
v4.1 より前の版が動いている時（`update` も自動更新も無い時）は、代わりに次の1行を貼る:

```lua
local o, ok = hs.execute("git -C ~/Document/line-dump pull --ff-only -q origin main 2>&1", true); print(o); if ok then hs.reload() else hs.alert.show("git pull に失敗（コンソールを見る）", 5) end
```

`sync.sh` は main 以外のブランチでは取り込み・push をしないので、Mac の clone は
main のままにしておく。

### 5. 手動テスト

1. LINE を開いた状態で `__LINE_EXPORT.status()`。✗ の行が無いか見る
2. `__LINE_EXPORT.check("Berry")`。Return を押したら手を離して触らない
   （触ると止まる）。✓ が「保存ダイアログ」まで並べば、保存の手前まで通っている
   （保存ダイアログはキャンセルする。保存はしない）。✗ なら、出てきた
   「次にすること」を見る
3. 1件だけ本当に書き出す: `__LINE_EXPORT.one("Berry")`
4. 全件: 集中モードを ON にして（通知バナーがクリックを奪うため）、`⌘⌥⌃L`。
   押したら手を離して触らない（触ると止まる）。
   最後に「LINE書き出し OK:n NG:0 / push済」と出れば成功（「push できず」なら
   書き出しはできていて push だけ失敗。理由は `mac/sync.log`）

GitHub の `chats/` にファイルが増えていることを確認する。

## 注意点（LINE 側の仕様なので回避できない）

- **画面に読み込まれている分だけが保存される。** 古い履歴まで欲しいトークは、
  初回だけ手動でトーク内を上にスクロールして読み込ませてから実行する
  （長く使っているトークは初回で数年分入ることが多い）。
  日によって取れる範囲が前後しても、取り込み側が重なりを見て結合するので
  正本の履歴は減らない
- 実行中は Mac を触らない（触ると止まる）。通知が押す所に重なると、その件は止まる
- LINE をフルスクリーンにしない（別 Space になり操作できない）
- 表示名がまったく同じトークが2つあると、上にある方を開く。
  区別したいときは LINE 側でどちらかの表示名を変える
- トークの表示名が変わったら（相手が名前を変えた等）、保存名が合わずに
  「保存ダイアログ」の段で止まる。`TARGETS` を新しい名前に直す

## うまくいかないとき

まず `__LINE_EXPORT.status()` と `__LINE_EXPORT.check("トーク名")`。
次に `mac/heartbeat.txt` の失敗した段と、Dropbox の `Backups/line-dump-debug/`
（`latest.txt` に段ごとの経過と、失敗した時の画面の並び（伏せ字）、同じ名前の画像）。

| 段 | よくある原因 | 対処 |
|---|---|---|
| 窓 | LINE の窓が開かない・検索欄が読めない | LINE を手で開いて、トークの一覧（検索欄のある画面）を出しておく。緑のボタンでフルスクリーンにはしない（窓の大きさは自動で画面に合わせる）。別窓で開いたトークは閉じる。アクセシビリティの許可を確認 |
| 窓 / 保存ダイアログ（保存ダイアログを閉じられない） | LINE の保存ダイアログを自動で閉じられなかった | ダイアログの「キャンセル」を手で押して閉じ、もう一度 |
| 全件: 画面収録が許可されていない | 画面収録が未許可 | 手順 3。許可後に Hammerspoon を再起動（直れば次の確認で自動で始める） |
| OCR（詳しく: 画面を撮れない） | 画面収録が未許可 | 手順 3。許可後に Hammerspoon を再起動 |
| OCR（それ以外） | `osascript mac/ocr.applescript` が動かない | ターミナルで `osascript ~/Document/line-dump/mac/ocr.applescript <画像>` を試し、出たエラーを Claude に見せる |
| 検索欄 | 検索欄にフォーカスが入らない | LINE を手で開き、検索欄をクリックできるか確かめる |
| トーク選択 | 一覧にも検索結果にも名前が出ない | `TARGETS` の名前を LINE の表示どおりに（`⌘⌥⌃J` で確認） |
| トーク確認 | 別のトークが開いた・ヘッダの名前が読めない | `latest.txt` の「ヘッダ行」を見る。`diag()` の「一覧とトーク欄の境目」がおかしくないか |
| メニュー | ⋮ の位置が変わった・項目名が変わった | `diag()` の「⋮ を押す位置」を確認。項目名が変わっていれば `SAVE_LABELS` に足す。⋮ の位置は `L.MENU_FROM_RIGHT` |
| 保存ダイアログ（保存名がトーク名と合わない） | トークの表示名が変わった・別のトークだった | Dropbox の `names.txt`（今のトーク名と、`TARGETS` ごとの一番近い名前）を見て `TARGETS` を今の名前に直す |
| 保存ダイアログ（それ以外） | 保存シートが出ない・別のダイアログ | 画像を確認。ダイアログが別の所に出ていないか |
| 移動 | 保存したファイルが見つからない・移せない | 保存ダイアログの既定の保存先を確認（ダウンロード・書類・デスクトップ・Linetxt なら自動で探す）。移せないときは「ファイルとフォルダ」の許可 |
| 保存 | 日付を付けられず、同名ファイルがあった | 過去の書き出しを上書きしないよう止めている。保存ダイアログの名前欄を手で確かめる |
| クリック | 押す所に通知などが重なっていた・前に出し直しても他のアプリが前にあった | 集中モード ON。コンソールに「前面: ○○」と、その時の前面のアプリが出る |
| （note: 中断） | 実行中に人がマウスやキーボードを触った・20分を超えた | 離席中に自動でやり直す。すぐ欲しければ `⌘⌥⌃L`。触っていないのに止まるなら、コンソールの「見張り:」の行の数字を見る |
| （note: 見送り中） | 画面ロック中・使用中・カメラ使用中・画面スリープを止めているアプリがある | `status()` で理由を確認。起こしておくだけの道具なら `KEEP_AWAKE` に名前を足す |
| （heartbeat が更新されない） | 昼以降も Mac がスリープ・電源オフ・ログアウトしていた（Hammerspoon が動いていない）・Mac の clone が main 以外のブランチ | `status()` で ✗ の行を見る。✗ が無ければ Mac が眠っていた（診断の「最近の眠り・ロック」に時刻が出る）。起きている間に3分触らなければ始まる（起きていてロック中なら、昼に「見送り中」が heartbeat に出る）。LINE が起動していなかっただけなら、次の確認で起動して走る |
| push できず | 認証切れ・main 以外のブランチ | `mac/sync.log` を見る。`cd ~/Document/line-dump && git push` を手で叩いて確認 |

ログは `~/Document/line-dump/mac/sync.log`（取り込み・push の結果）と、
Hammerspoon コンソール（各トークの OK/NG。画面の文字は伏せ字）。

それでも分からない時、または「この Mac ですることは無い」と出た時は、
Claude に「LINE書き出しの診断を見て直して」と頼む（Dropbox の `latest.txt` と
画像を見て、直した版を出す）。

## 取り込みだけやり直したいとき

書き出し済みの txt を入れ直すだけなら Hammerspoon 不要:

```bash
bash ~/Document/line-dump/mac/sync.sh
```
